## 启动与检查

本机验证环境为Node.js26.7.0。依赖使用pnpm，锁文件已随仓库保存，声明与锁文件一致。原工作流使用pnpm11.22.0。可先安装这两个版本，然后执行：

```sh
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
pnpm exec vitest run
pnpm exec taro build --type weapp --no-check
```

本机曾遇到普通微信构建的macOS检查器阻塞，因此命令显式带--no-check，类型检查单独执行。不要因为构建成功就推断线上云函数或手机界面已验收。

立即预览：微信开发者工具导入“微信开发者工具导入包”目录。重新构建前端后，可导入项目根目录，project.config.json会读取dist/。本仓库保留了原Windows打包脚本；Mac可以直接导入根目录，无需运行Windows脚本。

本地演示模式：

```sh
TARO_APP_DATA_MODE=local pnpm exec taro build --type weapp --no-check
```

生产构建默认连接真实CloudBase。AppID和环境ID是客户端公开标识，不是访问凭据。朋友需要另行获得小程序开发者身份以及CloudBase权限。

## 云端与本地的区别

2026年10月1日已部署并下载核对stats、match、team、membership四个云函数。10月15日仅整理接力包，没有重新部署云函数，也没有导出最新数据库。

云函数开发入口统一为cloudfunctions-src/，导入包内9个函数的index.js和common.js均与源码逐字节一致。直接修改源码，然后执行：

```sh
pnpm exec node scripts/build-cloudfunctions.mjs
```

生成的cloudfunctions-dist/可用于部署。朋友无需在多份代码之间选版本。team以本次已部署的稳定版本作为接力起点；本机另有未上线改动，完整保存为docs/archive/team-unpublished-changes.patch，普通开发不需要应用该补丁。

接力仓库只保存代码和部署包，不会因下载、推送或构建而自动覆盖生产云函数。生产部署需要已有权限，按改动范围选择函数即可。其他函数和消息回调服务的线上状态需要重新检查。

## 数据与账号

保留项目原有fixtures作为源码的一部分，其中包含球队名册和历史示例，，按所有者要求公开交付。真实云端数据库、球员会费与成员资料备份、本机浏览器资料、依赖缓存、登录态和上传密钥均未打包。已有完整备份在原维护者本机，不要把这些备份放进GitHub。

仓库公开，朋友可以直接下载ZIP或git clone；需要直接推送时，再由所有者在Settings→Collaborators中邀请。微信开发者身份和CloudBase权限需分别授权，不共享个人登录凭据。

微信上传工作流改为仅workflow_dispatch手动触发，新提交不会自动覆盖体验版。工作流需要MINIPROGRAM_PRIVATE_KEY这个GitHub Secret，本仓库没有配置或迁移密钥；该自动上传流程未在接力仓库验收。正式发布和审核仍由维护者在微信后台操作。
